# 她給你的卡:抽卡與立繪

2026-11-09 起草。現況見 `packages/api/src/card.ts`、`packages/card-face`、`docs/OPERATIONS.md` 的卡片段落。

## 0. 一句話結論

立繪不再是 10 張固定截圖。發卡時用她的 Live2D 模型在機器上現場擺出一個姿勢、拍一張去背圖:表情跟著關係,手上的東西、配件、角度、背景照公開的機率抽。每張卡都長得不一樣,有稀有度,慢慢長成收藏;但卡還是「她眼中的你」的快照,不拿來交易。

## 1. 現況

- 一天最多 5 張,每張是發卡當下關係的快照:分級文字、她寫的一句話、印章、她選的欄位。
- 立繪 10 張(`card-<pose>.local.webp`,同一套衣服、同一個角度,只有表情不同),依好感分組(`CARD_POSES`),組內隨機。
- 付費:重抽、指定立繪、框(sakura / abyss / gold)、閃卡。幣只能賺,不能用真錢買,也不能轉給別人(`economy.md` §2)。

變化太少:抽幾張就看完了。

## 2. 原則

1. **模型檔不出機器。** 算圖在跑 Core 的機器上用無頭瀏覽器跑,只把 PNG 放進卡片。moc3 和貼圖不放上網頁。
2. **表情說真話。** 表情由關係決定,稀有度買不到、抽不到。好感很差的人不會抽到愛心眼。
3. **機率公開。** 每個池子的機率寫在卡片頁上,改機率要留紀錄。幣不碰真錢,所以法規上不是抽卡,但照抽卡的規矩做。
4. **稀有度不是好感。** 抽到 SSR 不代表她比較喜歡你,也不影響任何數值。
5. **卡是給你的,不能交易。** 卡上有你的名字、她怎麼叫你、她對你的感覺。轉給別人就不是那張卡了,而且開放交易就會有人開小號刷卡轉給大號,和「幣不能轉給別人」的理由一樣。

## 3. 一張卡由什麼組成

| 特徵 | 怎麼決定 | 模型裡的東西 |
|---|---|---|
| 表情 | 關係(好感分組),她在組內挑,或對方付費指定 | 臉紅、愛心眼、> <眼、屑屑眼、流冷汗、落淚、圈圈眼、黑臉、大牙、微笑等參數 |
| 手 | 抽 | 無、狗尾草、撫胸、豎食指 |
| 配件 | 抽(可以沒有) | 黑框眼鏡、單片眼鏡、大鋼盆、尾巴 |
| 服裝 | 抽 | 長裙、鞋子、胸口衣服 |
| 姿勢 | 抽,再加一點隨機的偏移,同一個姿勢每張也略有不同 | 見下表 |
| 背景 | 抽 | 見 §5 |
| 框、閃 | 付費(照舊),SSR 自帶閃 | |

「大小變」「加載」這類特效先不放,看過算圖再決定。

姿勢用 VTube Studio 實際在驅動的參數:頭 `AngleX/Y/Z`、身體 `PositionX/Y/Z`、前傾 `LeanInput`、視線 `ParamEyeBallX/Y`,其餘(肩、腰、頭髮、裙子)由模型的物理帶動。`ParamAngle*` 和 `ParamBodyAngle*` 這個模型沒有接,設了不會動。

| 姿勢 | 參數(大約) |
|---|---|
| 歪頭(左/右) | `AngleZ` ±28、`PositionZ` ±20 |
| 湊近 | `LeanInput` -30、`AngleY` -10 |
| 側身回頭(左/右) | `AngleX` ±30、`PositionX` ±25,視線看回鏡頭 |
| 抬頭 | `AngleY` 30 |
| 害羞低頭 | `AngleY` -30、`AngleZ` 16,視線往上看 |
| 搖擺 | `PositionZ` 30、`AngleZ` -20、`AngleX` 22 |
| 正面 | 全部接近 0 |

手上拿東西時手在腰的位置,這種卡的鏡頭要拉遠一點才拍得到手。構圖跟著特徵走。

## 4. 稀有度

先抽稀有度,再從那個稀有度允許的池子抽特徵。這樣機率表簡單,公開時也好懂。

| 稀有度 | 機率(草案) | 允許的東西 |
|---|---|---|
| N | 70% | 基本角度、無配件或一般配件、一般背景 |
| R | 22% | 加上手部動作、服裝變化、較少見的背景 |
| SR | 7% | 加上稀有配件(單片眼鏡、大鋼盆)、特殊背景 |
| SSR | 1% | 特殊背景、自帶閃卡、可能有配件組合 |

卡上會標稀有度,卡片頁列出這張卡抽到了哪些特徵。

## 5. 背景

不用遊戲美術。先用程式畫的:她的顏色的漸層、光斑、星點、水面、夜空,每種有幾個變化。之後 owner 有自己的圖(委託或自己畫的)再加進池子。

限定池(之後):她直播中發的卡才會出現的背景、節日、她的生日、唱到第 N 首歌之類跟她生活有關的時刻。

## 6. 算圖

2026-11-17 做了。程式:`tools/card-studio`(頁面和無頭瀏覽器)、`packages/play/cards/src/portrait-looks.ts`(對照表)、`portrait-backgrounds.ts`(背景)、`portrait-spec.ts`(抽到的東西 → 算圖規格)、`live2d.ts`(`CardPortraitKey` 的實作)。

- **怎麼算**:card-studio 的頁面用 Live2D 官方 Cubism SDK for Web(Core 5.1、Framework 5-r.4,`vendor/` 不進 git,見它的 `vendor.md`)載入她的模型。Core 用 playwright-core 開無頭 Edge(或 Chrome),依序套上:動作檔的最後一格(手勢)、參數、模型自己的表情檔(`Exp3/*.exp3.json`,照檔案裡的 Blend)、再加的參數;物理每張都從靜止重來、跑 2 秒;背景是一張 SVG 畫在她後面。結果是 900×1200 的 PNG(卡的畫框是 3:4),不透明,就是整張卡的立繪。
- **模型不出機器**:模型直接讀 VTube Studio 的資料夾(`[modules.cards] portrait_model`),不複製、不放上網頁;只有 PNG 離開。
- **同一張卡同一張圖**:規格只由部件、表情和種子決定(`portraitSpec`),物理每次重來;種子給頭的角度(X ±5°、Y ±4°、Z ±4°)、視線(±0.15 / ±0.1)、鏡頭遠近(±3%)和左右(±0.02)一點偏移,背景的星星、光斑、煙火位置也由種子決定。圖依規格的雜湊(加模型檔的大小和修改時間、`RENDER_VERSION`)存在 `data/cards/portraits/<雜湊>.png`,同一張卡只算一次,重開也還在;不見了就照快照重算出一樣的。發卡時就先算,卡片頁和連結預覽拿到時已經好了。
- **構圖跟著部件走**:每個部件說它要露出她的哪一段,取最低的那個。卡的下半是字,所以那一段放在圖的上 3%–47%:胸口以上(預設、手、眼鏡、表情)、頭上留空間(大鋼盆)、到腰(尾巴、長裙)、全身(換鞋)。
- **退回固定立繪**:沒設模型、card-studio 沒建置、少了 Live2D 的檔案、開不了瀏覽器,`render` 回 `null`,卡用 10 張固定立繪裡最接近表情的那張;日誌只寫一行,不是每張卡一行。連續失敗三次暫停十分鐘(再一行)。一次只算一張,最多四張排隊,再多的直接用固定立繪;一張超過 `portrait_timeout_secs` 就放棄並關掉那個瀏覽器。瀏覽器算完一直開著,閒置半小時才關。
- **效能**(這台,RTX 4070S 但無頭 Edge 用 SwiftShader):第一張約 2.9–3.1 秒(開瀏覽器、載入 5 張 4096 貼圖),之後每張約 0.5 秒;讀快取幾毫秒。
- **字型**:卡變成 PNG(resvg)時只用專案帶的 Noto Sans TC(`packages/card-face/fonts`,SIL OFL 1.1,400 和 700 兩個字重),不用系統字型。
- **看一眼**:`pnpm --filter @miyoria/card-studio build` 之後 `pnpm --filter @miyoria/card-studio sheet` 把每種稀有度一張、每個表情一張、每個部件一張畫成圖和整張卡,放在 `.tmp-test/cards-sheet/`。

### 6.2 限制

- 「換一雙鞋」要全身入鏡,她在卡上很小(臉約 75 像素寬);鞋子在畫面中段,看得到但不顯眼。
- 「短裙」和「平常的衣服」穿的是同一條裙子,差別只在構圖(到腰);模型沒有第三種裙子。所以「短裙」拿掉了(migration 9,不會再抽到、不能許願、不算進衣櫃系列),衣櫃系列剩平常的衣服、長裙、換一雙鞋、胸口的衣服。
- 姿勢之間的差別多半在身體和頭的角度,縮圖上不明顯;「湊近」「搖擺」「側身回頭」最明顯。
- 一張圖約 1 MB(PNG),每天 70 張約 70 MB。快取有容量上限(2026-11-17 加,見 [v5-play.md](v5-play.md) §10.2.3):`[modules.cards] portrait_cache_max_mb`(預設 2048),超過就從最久沒用到的刪起(讀圖時把檔案的修改時間改成現在,所以「最久沒用」看修改時間);刪掉的圖要用時照快照重算出一樣的。
- 圖還沒有進產物庫(`cards_card.artifact_id` 還是空的):快取依規格的雜湊存,不是依卡號;要進產物庫(可以分享、跟著卡保留)要再決定。
- 現場算的圖在連結預覽(`/og/card/<編號>.png`)、會員頁和卡片頁(`/api/public/card-art/<編號>.png`)、`/me card`(附整張卡的圖)都是同一張,取法見 [v5-play.md](v5-play.md) §10.2.3。閃卡的彩虹遮罩原本靠固定立繪的透明背景,現場算的圖是不透明的,遮罩變成整塊立繪;要不要重做等 owner 看過樣稿。
- 算圖在跑 Core 的那台電腦上。`renderer` 這個能力目前指的是直播機的 Stage,還沒有「別台電腦替 Core 算卡圖」的服務。

## 7. 往卡牌遊戲走(分階段)

1. **這次:** 現場算圖、特徵、稀有度、公開機率。
2. **卡冊:** 每個人看得到自己集到哪些特徵(圖鑑),集滿一個系列(例如「眼鏡系列」)給稱號。只看自己,不排名(面板規則:不排名任何人)。
3. **限定池:** §5 的限定背景和活動。
4. **玩法(待定):** 卡不拿來比強弱。如果數值來自關係,就等於把關係變成戰力,和「不排名」衝突。可以想的方向:拿卡和她互動(給她看某張卡,她會記得那天)、合成同系列的卡換特殊背景。

## 8. 要 owner 決定的事

- 稀有度機率(§4 是草案)。
- 交易:我的建議是不做(§2.5)。
- 「黑臉」「落淚」「圈圈眼」這種表情給哪些關係,還是只當 SR 以上的彩蛋。
- 付費指定立繪(`card_pose`)以後指定的是表情,還是整組特徵。
- 舊卡保持原樣。
- 模型授權:DeepSeek-chan 模型能不能拿來產生公開的卡片圖(直播已經在用,應該沒問題,但要確認作者條款)。
