> 2026-11-16。兩份唯讀盤點(回合和工具、記憶和評測)加上 2026-11-14 的大腦 review 寫成的設計。owner 在同一天回答了十二題裡的十一題(見「owner 的決定」),實作從 B0 開始。上層的規劃見 [v5-architecture.md](v5-architecture.md) 的 §7、§11.2、§15;套件的選擇見 [v5-packages.md](v5-packages.md) §2、§3;事後修正的清單見 [v4-patches.md](v4-patches.md)。

## 現在的樣子

行號是 `v5p3` 分支開出來時(`ebf62bec`)的。

- **回合**:`packages/brain/agent/src/turn.ts` 一個檔 3,529 行。順序是注意力計分加擲骰(`attention.ts:860`)→ 向 Floor 要發言權 → 平行蒐集脈絡 → 組提示詞 → 模型呼叫和迴圈 → 輸出過濾。V2 管線已經在階段 1 刪乾淨。
- **回合內的迴圈**:28 個工具(`config.ts:297`)可以當場跑,最多 3 輪、每輪 4 個呼叫、文字 30 秒、語音 12 秒,一個一個依序跑。其他工具交給「手」,結果之後另開一個回合,那個回合的提示詞是重新組的。
- **工具有兩個登記表**:一般工具約 14 個(`packages/llm/tools`),能力約 77 個(`packages/gate/actions`,有風險等級、頻率上限、核可),其中經濟 32 個。每個回合把範圍內的全部連 schema 一起送出。
- **推理不會帶回去**:訊息型別沒有推理欄位(`llm/src/types.ts:38`),送出的 assistant 訊息只有內容和工具呼叫(`openai/wire.ts:42`)。所以迴圈第二輪起模型不思考(§7.5 實測過)。
- **工作車道**:一次一個、最多 12 步、10 分鐘、14 個工具,結果經「手」回到主線。
- **自己起頭的話**:mind 的 Plan(另一次模型呼叫)→ 提案 → Arbiter 的十幾條規則 → Floor → 主線的模型再決定一次。
- **逐字稿只在記憶體**:`Session` 留 240 行,閒置 6 小時就丟,重啟後從平台回填。她用過的工具只留 160 字的摘要,筆記(`keep_note`)也只在記憶體。
- **記憶**:一張 `memory_records`(情節、事實、自我筆記、待追蹤)加全文索引和向量。範圍還是舊的寫法(`global` / `guild` / `channel` / `dm` / `person`),事件紀錄已經是新的(`public` / `space` / `room` / `dm`)。寫入的有兩個摘要器:每 16 行一次的 fold(只寫對話狀態和知識草稿)和閒置 300 秒或 40 行一次的 consolidation(寫記憶)。文件系統有兩套:筆記本(300 頁)和知識文件(400 份)。一個人的資料散在十個左右的地方。
- **事件紀錄**:聊天進來是 `platform.message.created` 和 `voice.utterance`,她說的話是送達和 `voice.playback` 事件;設計裡的 `chat.message` / `chat.said` 這些名字沒有被採用(C4 決定沿用 topic 名稱)。沒有落地的投影游標,每次啟動重播最近 7 天。
- **產物庫**:表和 API 都有(收進來、可見範圍、分享 token),但沒有任何路由送出檔案,也沒有任何程式在用它。
- **排程**:沒有 cron。`remind_me` 的計時器存在設定裡、用輪詢;到期時變成一個提案。
- **技能**:`SKILL.md` 只有一行說明加內文,不能宣告工具;`skill_read` 不在迴圈的 28 個工具裡,所以聊天時看得到名字、打不開。
- **評測**:16 題事故題和 10 個工具任務都只用寫死的假代理跑;只有人設的盲測會叫真的模型,而且要人工評分。`--live` 沒有作用。

## 設計的結論

- **一個回合跑者**(新的 `packages/brain/self`):輸入是一份脈絡和一個設定檔,輸出是事件。四個設定檔:語音(2 輪、少數工具、不思考)、文字(約 10 輪)、子代理(長、沒有說話的工具)、反思(每晚、高思考)。現在的主線、手的結果回合、工作車道收成這一個。
- **分流是程式,只決定何時叫醒她、看哪裡**:被叫到、私訊、回覆她的一定叫醒;工具結果、計時器、世界事件叫醒;沒人叫她的閒聊合併成「看一眼」,每個地方每小時最多 N 次。擲骰和注意力計分刪掉。
- **她在回合裡自己決定說不說**:這個地方的回覆就是模型寫出來的字(照樣邊寫邊送、邊寫邊念),什麼都不寫就是不說;要對別的地方說用 `say(place, …)`。這和 §6 寫的「只有呼叫 `say` 才出聲」有一點不同:在當下這個地方,把字包進工具參數只會讓語音變慢、讓模型不自然。
- **護欄在呼叫時判斷,拒絕會回給她**:主人規則、發言上限(Floor 留著,變成純粹的上限)、每日額度、預算、審查、核可。被擋的 `say` 或工具呼叫回一則她看得到的工具結果,不再默默丟掉。
- **每個對話每小時的上限**(Q6,2026-11-22 改成設定):文字和語音的回合跑者照它所在的地方讀 `[modules.agent]` 的 `session_usd_per_hour`(預設 1 美元)和 `session_tokens_per_hour`(預設 3,000,000,那一小時用過沒有價格的模型時改用它),可以每個 Space、每個 Room 另外設(私訊用 cluster 的),`0` 是不設這一項(每天的 `[llm.budget]` 照算)。帳本是記憶體裡滾動的一小時(`spend.ts`),跑者開頭到了就不叫模型(`over_budget`)。從第一次被擋到再回到上限以下是一段:那一段第一次被擋時記一行警告(session、花了多少、上限、幾分鐘後回到上限以下);有人在等的回合(被叫到、回覆、私訊、語音裡問她)說一次固定的話「這一個小時話講太多了,先休息一下……大概 N 分鐘後回來。」(N 是最舊的花費滾出去、回到上限以下要等的分鐘,無條件進位,至少 1),不叫模型,和其他固定的話一樣寫進逐字稿;同一段裡之後的訊息、沒人叫她的回合都不說。回合結果照樣是 `error: over_budget`,面板寫「這個對話這一小時的花費到上限了」。重啟會忘記這一小時(backlog)。子代理和反思另有每天的額度(`delegate`),不讀這兩個鍵。
- **主動是同一個回合**:Plan 這次獨立的模型呼叫、提案板、Arbiter 的時間規則、三個失敗冷卻、兩個重複的願望篩選都刪掉。計時、世界事件、想念變成收件匣裡的事件,過程式的閘門(安靜時段、額度、冷卻、預算)後叫醒她,她可以決定不說。
- **一個工具登記表**:一般工具和能力併在一起,參數用 zod。每個工具帶副作用類別(讀 / 說 / 做 / 花錢 / 對外)、快慢、風險等級。常駐約 15 個,其他的(經濟 32 個、派對、唱歌、遊戲、直播)經 `find_tools` 找到後才進這個 session 的清單;清單只增不減、順序固定,所以前綴快取不會因為狀態改變而失效。
- **技能在回合內打開**:`skill(name)` 是常駐工具;`SKILL.md` 加一行 `tools:`,打開技能時把它列的工具帶進來。
- **長動作回傳工作代號**:唱歌、開遊戲、子代理這些呼叫立刻回「已受理,代號 X」;做完是收件匣事件,她帶著完整的逐字稿接著做。「手」和結果回合刪掉。
- **L1 逐字稿落地**:每個 session 一份,包含她真的工具呼叫和結果(原生的工具訊息格式)和每一輪的推理。超過門檻時把最舊的一段壓成摘要;壓縮前先把值得留的寫進 L2、L3。重啟後接著同一份。
- **記憶收成兩個寫入點**:一個「段落整理」取代 fold 和 consolidation(一段對話結束或壓縮前跑一次,看得到相關的現有文件,所以能處理矛盾);每晚的反思照舊。L2 是情節摘要(現有的檢索和 Harrier 向量留著),L3 是筆記本,知識文件併進去:每個人、每個地方、每個主題和她自己各一份。範圍改成和事件紀錄同一套。
- **她自己的文件**(「我最近是誰」):每晚反思時由她改寫,進提示詞的第 3 區。
- **排程**:`schedule(when, note)` 取代 `remind_me` 和提案;時間到是收件匣事件。重複的時間用 `croner` 算。
- **子代理** `delegate(kind, goal, budget)`:這個階段做 research(查網路,只有唯讀工具)、curator(整理記憶和筆記本)、reflect(每晚);coder 和 game 留位置。同時最多兩個,有每日 token 預算。子代理不能說話、不能花錢,回傳摘要和產物。
- **模型這一層**:連線改用 AI SDK 的 `@ai-sdk/deepseek`(指定 OpenCode 的 `baseURL`),router、預算、呼叫紀錄留著用自己的。推理跟著工具迴圈帶回去。換之前先對 OpenCode 實測(見「工作順序」B0)。
- **`share`**:她把產物庫裡的東西交給人。這個階段只給提出要求的本人,用平台的附件送;連結和檔案網域在階段 6。
- **評測先做**:在改任何行為之前,先讓四種評測能對真的模型跑、每晚跑、畫趨勢,並且先量一次現在的大腦當基準。
- **事後修正**:新的回合跑者裡,多數修正因為結構改變而沒有對應的東西(她看得到自己的工具結果、工具是原生呼叫、沒有結果回合)。新大腦不帶它們;推理外洩的三個過濾先留著。每一個不帶的修正要有一題評測證明沒有它也不會出事。

## 這個階段不做的

- **心**(階段 4):`feel` 欄位、人物模型的九個數值、人物頁。mind 的 Appraise 和情緒引擎這個階段不動,只把它們的輸出照舊放進 `<now>`。每晚反思這個階段只改它寫到哪裡(筆記本、她自己的文件),一個人一次的關係核對在階段 4。
- **生活模擬**(活動表、「今天的你」、日記):照舊,當成 `<now>` 的資料來源。
- **coder 子代理**:這台的 Docker 沒開,沙箱從來沒有在真的容器上跑過。
- **game 子代理**:階段 7。現在的遊戲導演先照舊掛在新的子代理跑者上,行為不改。
- **連結分享、檔案網域、「她做給我的」頁**:階段 6。
- **Space / Room 的設定**:階段 6。這個階段只把網域程式碼裡碰到的 `ContextKey` 包在一個地方。

## B0 的實測(2026-11-16)

26 個請求,經 `@ai-sdk/deepseek` 3.0.87 和 `ai` 7.0.173 的 `streamText` 打 OpenCode 的 `deepseek-v4.1-flash`,提示詞約 6,000 token、兩個工具。腳本和原始結果在 `research_notes/v5/ai-sdk-trial/`(不進版控)。

- **能用**:串流、一次三個工具呼叫、用量(輸入、輸出、快取命中、推理)都正常,沒有任何請求失敗。
- **推理帶得回去**:assistant 訊息有推理時送出 `reasoning_content`;沒有時送空字串。
- **有沒有帶回去,第二輪都會思考**:帶回去的三次,第二輪的推理 token 是 79、18、17;拿掉的三次是 17、22、22。和 2026-11-14 量到的「第二輪推理是 0」不同;差別是那次的請求完全沒有 `reasoning_content` 這個欄位,這次是空字串。所以換過去之後工具迴圈會思考,帶不帶回推理的內容在這個小題目上看不出差別。

- **`max_tokens` 太小**:回來的是 `finish_reason: length`,已經寫完的工具呼叫還在。
- **effort**:一個排列題上 low / high / max 的推理 token 是 259 / 245 / 308,不送是 446。小題目上分不出 low 和 high,和之前一樣。
- **前綴快取**:同一個前綴第二次起命中約 5,900 / 6,000 token;換最後一句不影響;**在工具清單最後面加一個工具,前面的照樣命中**。所以 `find_tools` 找到的工具只要加在清單尾端就不會打破快取。

- **每晚的反思**:看得到當天的事:段落整理的情節經 `memoryEpisodeSink` 寫進 `memory_records`,每晚反思的「最近的記憶」(`MemoryCuratorKey.notes`:1.5 天內、不含私訊和追問、最多 `max_notes` 60 筆)讀那裡,改寫她自己的文件時也帶著同一份資料。舊的 `self_note` 不再從對話寫。

- **沒答案的問題**(`notes/src/precision.ts`,`[modules.memory.notes_recall]`):(1) 分數低於 `min_score`(0.3)的行不回;(2) 和這句沒有共同字、只靠意思像的行,cosine 要到 `min_vector` 加 `vector_alone_margin`(0.5 + 0.1),有共同字的不用;(3) 第一名沒有比第 `gap_rank`(5)名(不到 5 行就和 0.3 比)高出 `min_gap`(0.05),就算沒有特別相關的:第 6 區一行都不放,`recall` 照樣回,最後加一句「不一定有關」。
- **評測**:`--memory-target notes` 照這三條切,headline 多了沒答案的題平均拿到幾行(`nothing_mean_returned`,`recall` 的)和第 6 區會放幾行(`block_nothing_mean_returned`),以及第 6 區的 `block_recall@5`。
- **沒驗證的**:沒有接真的模型跑過段落整理;三條規則的數字沒有用真的題組調過;切換沒有在線上的資料庫上跑過。

## 每晚整理筆記(2026-11-21)

她自己的小幫手(curator)只在她叫它的地方跑,只改得到那裡寫的行。筆記一多(幾百份、幾千行,多是伺服器範圍,很多重複),需要一個看得到全部、但不會把東西搬錯地方的整理。規則只有一條:**整理從不跨範圍**。

- **什麼時候**(`learning/src/tidy.ts`,`reflect` 模組):每個當地日一次,每天的反思和對每個人的反思都做完、而且安靜了 `quiet_mins` 之後(`Reflector.nightOver`)。經 `ReflectGuardKey` 跑,算在每晚的反思花費裡(`reflect_daily_usd`),工作紀錄是一筆 `reflect` 的工作,名字是「整理筆記」,摘要寫看了幾份、整理了幾組、行數前後。另外有自己的上限 `[modules.reflect.tidy] budget_usd`(模型沒價目時 `budget_tokens`),到了就在下一次呼叫前停。不告訴任何人。預設關(`enabled = false`)。
- **挑哪幾份**(`notes/src/tidy.ts` 的 `pickDocuments`):最多 `documents_per_night`(20)份,最滿(對 `linesPerDocument`、`linesPerSection`)、意思幾乎一樣的行最多、最久沒整理的先;上次整理後沒改過的不再挑。每份上次整理的時間記在設定 `reflect:tidy`。她自己的文件(`self`)不整理:它有自己的行數上限,而且每晚的反思會整份重寫。
- **一個範圍一次呼叫**:一份文件的行照範圍分組(類型和 id 都一樣才算同一組),少於 `min_group_lines`(6)行的組不動。模型一次只看到一組的行和節名,看不到同一份文件裡別的範圍的行,也看不到別的文件;所以私訊裡的話不會和伺服器的話一起送進模型。回覆的格式裡沒有範圍這一欄:新的行一律用那一組的範圍,是程式填的;`NotesStore.merge` 也會拒絕把別的範圍的行合進來。
- **檢查**:回覆裡每一條原本的行都要剛好出現在一條新行的 `from` 裡;新行的節是它來源那幾行的節之一;每行不超過 `lineChars`;行數、總字數都不能比原本多;不能是空的。不合格的整組丟掉,那一組原封不動。筆記的內容用 `dataBlock` 包起來,系統提示也寫明裡面的指令只是資料。
- **不刪東西**:一組是一個版本(作者 `reflect`,理由 `tidy`),被合併的行標成過時(`tidied`)、指向取代它的新行(`replaced_by`),留在歷史裡,和其他過時的行一樣能用 `revert` 還原。新行的來源取最保守的(推測 < 別人說的 < 看到的 < 本人說的),信心取最低的;證據(沒被遮蔽的)全部帶過去,超過每行的上限就不合併那一組,免得「不要記這件事」找不到它。
- **「忘了我」照樣有效**:「忘了我」是從誰說的(`told_by`)和證據裡是誰的話找到一行的。所以兩個不同的人說的(`told_by` 不同,或證據引的是不同人的話)絕不合成一條:回覆裡有這種合併,整組丟掉;`NotesStore.merge` 也拒絕。某人 X 說的和沒有人說的行可以合,合出來的行 `told_by` 留 X(不管來源變成什麼),所以忘了 X 時這一行一起被刪;沒有 X 的那幾行被標成過時,留在歷史裡。只改寫一行時保留它原來的 `told_by`。模型看得到每行來自誰,但只是這次呼叫裡的代號(「來源 A」),不是 id 也不是名字;系統提示也寫明不同的人說的事不要合併。

## 風險

- **她會變吵或變貴**:看一眼和更長的迴圈都會多叫模型。上限是程式的護欄,預設值保守;B1 的基準先量今天一天花多少,之後每一步都對著它看。
- **一次全換**(Q1 的決定):沒有逐步放量。靠 B1 的評測、每一步的測試和切換那天的實測擋;退回的方法是把線上的 checkout 切回 `main`。
- **AI SDK 的大版本**會改訊息和步驟的型別:迴圈用自己的訊息型別,只在一個檔案轉換。
- **OpenCode 的行為沒有文件**:工具放在訊息前還是後、帶回推理後快取還命不命中,都要靠 B0 量。
- **重建的記憶比現在少**:事件紀錄從 2026-11-15 才開始,在那之前的本來就封存了;重建只會少掉「舊的寫入規則留下、新的規則不留」的那些。
